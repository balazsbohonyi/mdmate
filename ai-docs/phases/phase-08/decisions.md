# Phase 8 decisions

Choices made while building, in the order they were made. The settled design is in `plan.md` and the `ISA.md` Decisions row of 2026-11-14; nothing here re-opens it.

## P8-T1: settings core

- **The built-in excluded list has 21 names, not 20.** `EXCLUDED_DIRS` in `src-tauri/src/fs/exclude.rs` was counted in P8-T1. The plan's "20 built-in names" and ISC-367's "the 20 names" were a miscount. ISC-367 now names no count; `tests/lib/excludedParity.test.ts` reads the Rust file and checks that the page's `BUILT_IN_EXCLUDED_FOLDERS` is the same names in the same order.
- **One validator, in the page.** `src/lib/settingsFile.ts` holds a table (`SETTING_DEFS`) with each key's file path, default, check and equality. Parsing, the screen's rows and the edit logic all read that table. Rust never parses the file, so it cannot disagree with the page. In P8-T1b the page pushes the validated values Rust needs (paste folder, recent caps, excluded folders, devtools); Rust checks the few that guard a boundary again (paste folder, folder names) before it acts on them.
- **A bad value keeps its last good value.** `settingsAfter` takes the values in force before the text: a key the file holds a good value for takes it, a key it holds a bad value for keeps its last good value and is flagged, a key it lacks goes to its default. On the first load nothing good was held yet, so a bad value starts on the default. A file that is not one JSON object changes nothing.
- **The line in the banner is the engine's.** `JSON.parse` reports a position; the line comes from it (or from the engine's own "line N column M"). For a missing comma that is the line of the next key, where the parser noticed. The message says "stops making sense at line N", not "the error is on line N".
- **Writes read the file fresh and go one at a time.** `changeSetting` reads `settings.json` again just before it edits, so a hand edit made a moment ago is not lost, and a queue runs changes asked for together in order. The page applies its own write at once; the watcher then finds the text it already holds and does nothing. The watcher waits for the queue to drain before it reads, so a quick second change is not undone by the echo of the first.
- **A file that is not valid JSON is never overwritten.** A change from the screen against such a file refuses, shows an error naming the line, and writes nothing (ISC-386); the user fixes the file, and the banner goes when they do.
- **A default on a missing file writes nothing.** Setting a key to its default when `settings.json` does not exist does not create the file.
- **`MDMATE_LINKS_ON_RENAME` (ISC-320).** While it holds `ask`, `update` or `never` it wins over the file for that run (`moveWithLinks` reads the override first, as before); the settings screen locks the row (P8-T1d, ISC-369). With it unset the file decides. Any other value is ignored, as before.
- **The watcher is on the data folder, filtered by name.** `settings/mod.rs` watches the data folder non-recursively (a program that saves by replacing the file would end a watch on the file itself on some systems, the reason `workspace/watch.rs` does the same) and reports after 100 ms of quiet. It reports the app's own writes too; the page compares text.
- **Key order of integer-like unknown keys.** The file is rewritten by `JSON.stringify` of the parsed object, so a duplicate key keeps its last value and integer-like keys (`"1"`) sort first. Both are JSON-spec behaviour for objects, and no setting uses such a key. Unknown keys always survive; their order is only exact for ordinary names.

## P8-T1b: the behaviour behind each key

- **Paste-folder characters are stricter than the plan.** Each part allows letters, digits, `-`, `_` and `.` and no trailing dot. A space, `%`, `#`, `?`, `(` or `)` in the folder would make `![](folder/name.png)` need escaping, and this is the one place a pasted link is built. Rust (`clean_paste_folder`) and the page (`checkPasteFolder`) read the same 46 cases in `tests/data/paste-folders.json`; a change to one fails the other's test.
- **A draft's images stay in `assets`; the setting applies at Save As.** A draft has no folder to put a nested path next to. Save As copies the images it uses into the new setting's folder and rewrites the links to it, also when a name did not change (the folder did). `rewrite_links_into` and `renameEdits(…, folder)` are the Rust and page halves.
- **One command pushes the runtime values, and Rust checks them again.** `settings_apply` carries the paste folder, the recent caps, the excluded names and `devtools`. The page validates first and pushes only when the JSON changed, one push at a time; Rust re-validates (`settings/runtime.rs`) and refuses the whole batch if one value is wrong, so a page that skips its check cannot move a boundary. A failed push shows one warning and the next change tries again.
- **The excluded list is a process-wide value, with a test lock.** `fs/exclude.rs` holds the list the walker, the watcher and the index all read, so one change reaches every reader. A changed list queues a scan for every root (`rescan_all`). Tests that need a stable list hold the read end of `LIST_GUARD`; the one test that changes it holds the write end.
- **Developer tools.** The `devtools` Cargo feature makes `open_devtools` exist in a release build. The window config says `"devtools": false`, so F12 does nothing natively; the command `devtools_open` (palette command, keybinding F12) opens them only while the setting is on. In the debug rig `open_devtools` worked with the config at false. WebView2 on Windows has no API to close an open developer-tools window, so turning the setting off stops new opens and leaves an open one open.
- **The recent caps are read where the list is read.** `RecentStore` keeps its two caps in atomics, set by `settings_apply`; a cap lowered cuts what is shown at once and what is kept at the next record.
- **Word wrap reaches open views by a transaction.** `wordWrap` is a `contentAttributes` function plus a tracker of views; the store calls `refreshWordWrap()` when the value changes, which dispatches an empty transaction to each tracked view. The `no-vue-in-editor` rule keeps Vue out of `src/editor`, so the store, not a watcher in the editor, drives it.

## P8-T1c: the Settings tab

- **A third tab kind.** `settings` joins `markdown`/`text` and `image` in `workbench/tabs.ts`. It holds a group (`appearance`, `editor`, `files`, `keyboard`, `advanced`, listed in `lib/settingsCategories.ts`, the one place both the workbench and the screen read). `docIdOf` answers undefined for it, so nothing that looks for a document is confused.
- **One tab by lookup, not by id.** `openSettingsTab` finds the Settings record in any pane and shows it (`selectTab` also makes its pane the active one); only when there is none does it open a tab in the active pane. `splitActivePane` copies the active tab's record for a file, and never for this one, so the new pane is empty.
- **Restore keeps one and ignores what it does not know.** A saved tab of a kind this version does not know is left out in `readSnapshot` (the layout loop then closes its place) instead of falling through to "open this path", which would have shown "could not be opened" or opened a file. Two saved Settings tabs: the first in the layout's order stays. An unknown group name becomes the first group. None of these gives a notice, since there is nothing the user can do about them.
- **The journal hears group changes.** A tab record changed in place does not change the layout, which is all the journal watched. `tabRecordsVersion` is bumped by `setSettingsCategory` and the journal watches it. `setImagePath` had the same gap; it is fixed after P8-T1f (see "After P8-T1f" below).
- **The gear is in the title bar.** Between the file name and the window buttons, same width as the menu button, with a hint that carries the shortcut. The plan says only "a gear button"; the title bar was chosen because every window has it and the status bar and sidebar header hold other things. The place is easy to move.
- **The screen is a shell for now.** `SettingsView.vue` draws the five groups and the heading of the open one, and says "This group has no settings yet." The rows are P8-T1d's. It loads with `defineAsyncComponent` in `PaneView.vue`; the plan says the view loads lazily, and no claim covered the architecture rule, so `settings-lazy` and its test (new ISC-389) landed here with the view.
- **Open settings.json is an ordinary text tab** through `settingsFile()`, which makes the file when it is missing and grants that one path. The warning about unsaved edits to it is P8-T1d.
- **The tests use a poll for the first load.** The first test that shows the screen waits for the fetched component (`vi.waitFor`); a fixed number of flushes was not enough on the first load.

## P8-T1d: the screen

- **One row, one table.** `features/settings/rows.ts` lists each setting's group, label, description and control; `SETTING_DEFS` stays the only place that knows values, defaults and checks. `SettingRow.vue` is the single row shell (label, description, key, dot and reset icon while modified, error and lock notes, a slot for the control). `SettingsView.vue` picks the control by kind: switch, number, text, choice, or the excluded-folders chips.
- **A control holds no value.** A switch or choice calls `requestSettingChange` at once. A number or text field keeps what is typed as a draft and checks it with the same `check` when it is left or Enter is pressed; a refused value shows its reason on the row and writes nothing, Escape drops the draft. A draft stays until it is accepted or dropped, so a hand edit of the file does not replace text you are typing into a field; a field with no draft always shows what the file says.
- **Rows that exist now.** Theme (one choice, Dark, until P8-T3), Word wrap, Large file size, Recent files, Recent folders, Image folder, Links on rename, Excluded folders, Developer tools, and an Open settings.json button row in Advanced that is an action and has no key. The fonts are P8-T1e's rows. The plan's Advanced group also lists Open keybindings.json and Open themes folder; they arrive with P8-T2 and P8-T3, which own those files. Keyboard says "This group has no settings yet." until P8-T2. A test lists the six font keys as the only validator keys with no row, so a key added later without a row fails it.
- **The search box.** Words must all match the label, description or key, ignoring case, across every group; the result list replaces the group, a click on a group clears the box. The action row is not searched.
- **The question about unsaved edits lives in the store.** `requestSettingChange` looks for an open, unsaved `settings.json` document (a document named `settings.json` whose path is the file's, so the file is not made just to look). If there is one the change waits in `pendingSettingChange` and the screen shows Save, Don't save, Cancel. Save writes the tab and then makes the change on top; Don't save reloads the tab (`revertDocument`, now also what the revert command uses) and makes it; a failed save keeps the question open and shows why. If the tab was closed while the question was open there is nothing left to save or drop, so any answer but Cancel makes the change.
- **An open, clean tab is brought up to date by the app.** After a write the store applies the change, then calls `refreshFromDisk` for an open `settings.json` document; a refresh that fails is a notice and the change stands. The browser mock's document watcher never reports the page's own settings writes, so a test could not see the real watcher; the real window was checked with the tab open and the result is in the ISA.
- **The switch was invisible.** Reka UI sets `data-state`, the generated Switch styles with `data-checked:` and `data-unchecked:`. `tokens.css` defines the two variants (only the switch uses them). `ui:add` leaves `tokens.css` alone, so a later re-add keeps the fix; `tests/styles/switchVariants.test.ts` fails if the generated file uses a variant the stylesheet does not define.
- **The Links row under the override.** `MDMATE_LINKS_ON_RENAME` makes the row show the value in force, disabled, with a note naming the variable and no reset icon. The dot still follows the file, which may differ.
- **Was open, fixed after P8-T1f:** `checkFolderName` accepted `..` as an excluded-folder name. It could never match a directory entry, so it did nothing. `setImagePath` and the session journal (from P8-T1c) were unchanged. Both are fixed under "After P8-T1f" below.
- **ISC-358 stays open.** Only Dark exists to look at. The line in tasks.md says it moves to P8-T3 with the P8-T1f commit.

## P8-T1e: the fonts

- **Custom properties, read only by the editor.** `editor/documentFonts.ts` sets `--doc-*` properties on the root from the live settings; only the editor's theme names them. The title bar, menus, tabs, sidebar and the Settings screen keep their tokens (a test scans `src` for any other reader).
- **Names are quoted.** A family field takes one name or a list. Each name is quoted (the generic keywords are not) and the list ends in the built-in stack, so an empty field, a name that is not installed and a name that is not valid CSS bare (`3270 Font`) all fall back and none drops the declaration. Headings fall back to the body family.
- **The default look is bigger.** The editor drew 13 px (inherited from the window); the plan's defaults are 15 px text and 14 px code (it was about 12 px). The heading multiples are the same, so the headings grow with the body. This is the settled default, but it is a visible change for anyone who never opens Settings.
- **Code size is a ratio.** The property holds `codeSize / size` and code is drawn at `calc(ratio * 1em)`. Body code and block code are exactly `fonts.codeSize`; inline code in a heading grows with the heading; code in a table is 0.95 x `fonts.codeSize` because table text is 0.95em. A fixed px size would have drawn code in an H1 smaller than the heading around it.
- **Fallbacks equal the defaults.** If `settings.json` cannot be read at start, nothing sets the properties, so the rules carry the defaults as `var()` fallbacks. A test keeps them equal to `DEFAULT_SETTINGS`.
- **Open editors measure again, once.** A font change asks each open view to measure its text again (`requestMeasure`); a change of another setting asks nobody.
- **The scale is one value.** Six boxes, checked together when one is left, written as one list; a reset takes the whole key out. The validator already refused any list that was not six numbers from 0.5 to 4.
- **Open:** the Theme row's list still holds only Dark (from T1d). The `..` excluded-folder name was fixed after T1f.

## P8-T1f: toggles and Switch Theme

- **A command can have a state.** `Command.state()` is true for On. The palette row and the menu item show On or Off at the right edge, read from the live setting (the same reactive read as `enabled`), so both follow a change made anywhere, including a hand edit of the file.
- **Toggles use the screen's change path.** `flipSetting` calls `requestSettingChange`, so a default takes the key out and unsaved edits in the settings.json tab hold the change. The question lives on the Settings screen, so a held change shows that tab (`changeSettingFromCommand`); without that the command would do nothing and say nothing.
- **Toggle Developer Tools is not Open Developer Tools.** The toggle flips the `devtools` setting; Open (F12) opens the window and is enabled only while the setting is on.
- **Switch Theme is a third palette mode.** `themes` lists `THEME_CHOICES`, marks the one in use, and a choice goes through the same change path. `THEME_CHOICES` moved to `lib/themes.ts`, so the palette does not import the screen's row table. With one theme the list has one row; it is built for several.
- **Focus returns to where the user was.** Switch Theme opens its list in the same tick the command palette closes, while focus is still in the palette's own box. `togglePalette` takes the origin the closing palette released (`justClosedFrom`) when the active element is inside a picker, so Escape or Enter on the list gives focus back to the editor and not to the page body.
- **ISC-371 and ISC-358 are P8-T3's.** Five entries and user theme files, and three themes to read the screen in, do not exist yet. ISC-395 holds what can be shown now.
- **ISC-249 stays open.** F12 in a release build needs a release build; I have not made one and it needs the owner's permission (it also builds with the `devtools` Cargo feature that T1b added).
- **The menu.** Toggle Word Wrap sits with the view items, Switch Theme and Toggle Developer Tools with the settings items. The state and a key share the right edge.
- **Open:** the menu's state rendering has no mounted test; a long menu scrolls in a small window, as it did.
