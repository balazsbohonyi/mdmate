# Phase 7: what was not tested, and how to test it later

Everything below was skipped on purpose or could not be done in the Phase 7 runs. Each entry says why, and how to check it when there is time. The decisions behind them are in [decisions.md](decisions.md).

| # | Gap | Why it was skipped | How to test it |
|---|---|---|---|
| 1 | Ctrl+F, Ctrl+H and F3 with focus in the file tree, in the real window (P7-T1) | The real run had no folder open (it used an untitled tab), so the tree could not take focus; Ctrl+Shift+E left the caret in the editor. Page tests cover it with the tree and panes drawn together (`treeFocus.test.ts`), which shows the tree does not cancel the keys but not what WebView2 does. | Open a folder, click a row so the tree has focus, press Ctrl+F, Ctrl+H and F3. Ctrl+F and Ctrl+H should open the bar with focus in its box; F3 should open it and leave focus on the tree. |
| 2 | Typing in the editor while the find bar is open on a large file (ISC-260) | The count itself was timed in the real window (20 to 26 ms for a rare word on 10.85 million characters, see decisions.md), but typing with the bar open was not measured: the scenario `typing-find-open` is written with the other perf scenarios at the end of Phase 7. | Open `realistic-10mb.md`, press Ctrl+F, type `e`, then type in the editor and watch for stalls; run `pnpm perf typing-find-open`. |
| 3 | Match marks in a table cell or an image caption while the table is drawn | The page test shows that Find Next reveals the source of a hidden table, frontmatter, link target and image source. Marks inside a drawn table widget (not selected) were not looked at. | Search for a word that appears in a table with the caret outside it. The word is in a widget; check that nothing looks broken. |
| 4 | Light theme look of the bar and the marks | The real run used the dark theme only. | Switch the OS to light mode (themes switch in P8-T3), open the bar and look at the marks and the toggles. |
| 5 | A very long line in the find box and a narrow pane | Not tried. | Split a pane to about 300 px wide and open the bar with the replace row; the buttons should not overlap the boxes. |
| 6 | Right-click on the bar in the real window | Pinned by a page test of the global guard, not run in the real window. | Right-click the find box and a toggle in the real app; no menu should appear. |
| 7 | Cmd+H on macOS (Replace) | `Mod+H` is Cmd+H on a Mac, which the system uses for Hide App. I did not check whether Tauri's default macOS menu takes the key before the page does. Mac builds only compile in CI; nothing ran. | On a Mac, press Cmd+H in the editor. If the app hides, rebind Replace on Mac (Cmd+Alt+F is the usual choice) in `defaultCommands.ts` and the menu test. |
| 8 | Folder search on a folder of tens of thousands of files, or on a network drive (P7-T2) | The perf scenario uses 8,016 files on the local disk (about 650 ms a search in a release build). A much bigger or slower folder was not tried. | Add a large source tree as a root, press Ctrl+Shift+F, search a common word and press Escape in the middle; the list should stay responsive and the search should stop within half a second. |
| 9 | Folder search on macOS and Linux (P7-T2) | Only Windows ran. The walker, the line reader and the paths are the same code as the link scans, but the path column of a result and the order of files were only seen on Windows. | Run `pnpm test:rust search::` and the real-window script on a Mac and a Linux machine. |
| 10 | Light theme look of the Search panel and its marks (P7-T2) | The screenshots were dark theme only. | Switch the OS to light mode (themes switch in P8-T3), search, and look at the marks and the selected row. |
| 11 | A narrow sidebar and a very long path or line in a result (P7-T2) | A long line is cut round the match in Rust and the page truncates with an ellipsis; a sidebar at its minimum width was not looked at. | Drag the sidebar to its minimum width and search for text in a deeply nested file with a very long line. |
| 12 | Search while a file is renamed or saved (P7-T2) | The search reads each file as it gets to it; a rename in the middle gives a result whose file is gone, and clicking it shows the usual open error. Not exercised. | Start a search over a big folder, rename a file that has a hit from the tree, then click that result. |
| 13 | Trusted-typing gate wording (P7-T2) | The first trusted run was under memory pressure with one run at 16.8 ms. The rerun on a quiet machine was 11.0 to 13.5 ms, but the perf script prints "repeatable: no" (the lowest run is 14% under the median). | Run `pnpm perf typing-during-search-trusted --runs 5` again on a quiet machine and read every run, not only the median. |
| 14 | Outline of a 10 MB unsaved edit on a release build (P7-T3) | The real-window run was on the debug build: an unsaved heading in the 10 MB file showed 1.76 s after typing (400 ms of it the wait), because the whole 10 MB goes to Rust. The release build is faster but was not timed. | Open `realistic-10mb.md`, show Outline, type a heading at the top, and time it to the new row on a release build. |
| 15 | Outline of a plain-mode file above 3 MB when the file is not Markdown (P7-T3) | A `.md` above 3 MB opens as plain text and still gets an outline (checked on the 10 MB fixture). The "not Markdown" message is covered by a page test with a small file; a large `.txt` was not opened in the window. | Open a large `.txt` and look at the Outline tab. |
| 16 | Two routes to one scan: document switch and active-tab watch (P7-T3) | Removing the document watcher's own scan on a switch does not change any test, because the active-tab watch scans too. I kept both on purpose, so no test can tell them apart. | None needed; if one is removed later, run the outline tests. |
| 17 | Light theme look and a narrow sidebar of the Outline panel (P7-T3) | Screenshots were dark theme and the default width only. | Switch the OS to light mode (themes switch in P8-T3), drag the sidebar to its minimum width and read the rows. |
