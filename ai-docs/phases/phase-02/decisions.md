# Phase 2 decisions

Deviations from the plan and choices it left open. Numbers carry the OS they came from.

## Checking the UI (all of Phase 2)

- **Same as Phase 1.** Browser checks use Claude in Chrome on `pnpm dev`; real-window checks use `pnpm tauri dev` with real OS input and screenshots over the WebView2 DevTools port (see "Checking the UI" in the Phase 1 decisions).
- **Rust tests never touch real files.** Fixtures are read from the repo and copied into temp folders before anything is saved.

## P2-T1

- **Rust owns the whole byte transform; the page owns the text.** `open_file` returns one raw frame: a JSON header, the line-ending exceptions as little-endian `u32` pairs, and the text as UTF-8 with `\n` as its only break (BOM stripped, UTF-16 transcoded). `save_file` takes the same frame back. Rust joins the endings, re-encodes with the original BOM and encoding, and writes. This was the advisor's call: the ISC-1 and ISC-2 probes are Rust tests, so the code that touches bytes has to be Rust. The layout is in the header comment of `src-tauri/src/fs/frame.rs`; the page's half (`src/platform/frame.ts`) arrives in T2 and must change with it.
- **Only the breaks that differ from the dominant ending are sent.** A plain CRLF or LF file carries no list; a mixed one carries a short one. The dominant ending is the most common one, the first to appear wins a tie, and `\n` when the file has no breaks. The pairs start on a 4-byte boundary (header padded with zeros) so the page can read them as a `Uint32Array` without copying.
- **A round-trip guard runs at every open.** If decoding, splitting, joining and encoding again would not give the same bytes, the document opens read-only (`not-round-trippable`) and a save is refused. This makes ISC-1 hold for any file, not only the fixtures. With a mutated `join` the fixture test failed and the random-bytes test still passed, because the guard turned the damaged files read-only: that is the guard doing its job.
- **Supported encodings: UTF-8 (with or without BOM), UTF-16 LE and BE (with BOM).** Everything else opens read-only as `unsupported-encoding` with every byte shown as the Latin-1 character of the same number, so nothing is dropped from view. UTF-16 without a BOM is not detected: it would be guessed, and a wrong guess can change bytes. Invalid UTF-16 (a lone surrogate, an odd byte count) is unsupported, since it could not be written back.
- **Atomic save.** A temp file next to the target (`.name.mdmate-<pid>-<n>.tmp`) is written, flushed with `sync_all`, given the original's permissions, then renamed over the target. A failure anywhere removes the temp file and leaves the original as it was. The test hook is a closure called just before the rename (`write_atomic_with`), so ISC-40's failure is injected without any global state. The target is the resolved path, so a symlink stays a symlink.
- **Path policy: the page may only touch files Rust saw the user choose, or files inside an open workspace folder.** `read_file` and `open_file` check every path (`src-tauri/src/access.rs`) against two sets: single files granted one by one, and workspace roots. Paths are compared resolved (symlinks and `..` followed), so a link inside a root cannot lead out of it, and case-folded where the OS ignores case. Network (UNC) paths are refused. Only Rust's own events grant: the open dialog today, a restored session in T6, a folder picker and launch arguments later. The page has no command that grants, because a page that can grant itself access has no limit at all. Phase 2 grants single files only; roots wait for Phase 6, so `grant_root` is built and tested but unused in a normal build (perf builds use it for the fixtures folder).
- **The page saves by a document id, never by a path.** Rust issues the id on `open_file` and remembers the resolved path, the format and the last known hash. Opening the same file again, however spelled, returns the same id (this is also what ISC-174 rests on). A save for an unknown id, a closed one or a read-only one is refused. The id travels in the `x-document-id` header, a plain number, because header values must be ASCII and file names are not.
- **Open dialog: `rfd` directly, not `tauri-plugin-dialog`.** The plugin pulls `tauri-plugin-fs` into the build graph (`cargo tree -i tauri-plugin-fs` shows it under the dialog plugin). It would never be initialized and the page would have no `fs:` permission, but ISC-21 says the crate is absent, and "absent" is the safer reading. `rfd` is what the plugin wraps, with the same feature set. The dialog runs in `spawn_blocking`, parented to the window, and the page gets no `dialog:` permission.
- **Case folding sits behind the platform trait** (`Platform::paths_ignore_case`: true on Windows and macOS, false on Linux), so `check-arch` keeps `target_os` inside `platform/`. macOS volumes can be case-sensitive; the default is assumed.
- **Mutation proofs (the code broken on purpose, then restored):**
  - `join` ignoring the exceptions: `roundtrip_unedited_gives_back_every_byte_of_every_fixture` and `roundtrip_unedited_through_the_file_system_keeps_the_hash` fail.
  - `encode` dropping the UTF-8 BOM: the same two fail.
  - Saving straight to the target instead of through a temp file: `atomic_save_failure_before_the_rename_leaves_the_original_intact` and `atomic_save_failure_leaves_a_missing_file_missing` fail.
  - The restored code passes all 67 Rust tests.
- **ISC-37 is not closed here.** Its probe passes (`save_writes_edits_in_every_supported_encoding`), but the claim says Ctrl+S, and the shortcut does not exist until the Save command is wired in T2. It closes there, as ISC-169 moved from T1 to T3 in Phase 0.
- **ISC-1 closes on the Rust probe.** The page half (the frame codec and the store passing text through unchanged) is covered by a web test in T2. If that finds a gap, ISC-1 reopens.

## P2-T2

- **The page keeps documents in a plain map and tells the chrome through a small reactive record.** `src/documents/store.ts` holds one `Document` per open file (editor state, saved snapshot, disk hash). Vue reads only `DocMeta` (name, path, dirty, read-only reason, last save error) from a `shallowReactive` map, so editor objects never enter Vue's reactivity (rule one). A document lives until its last tab closes, then the host is told with `close_document`.
- **Tabs are a `kind` union, and `TabInfo` now carries `kind`, `title` and `dirty`.** `TabRecord` has one member today (`markdown`, with a `docId`); Phase 6 adds text and image tabs as new members. The titles map from Phase 1 is gone: a tab's title is its document's file name. `workbench/store.ts` is still the only place that owns layout and tab records, and `splitTree.ts` is untouched.
- **A split opens a second tab on the same document.** This replaces the Phase 1 stand-in that copied the title. **Until P2-T3 lands, two panes on one document do not stay in step**: each view holds the state it was given, so typing in one is not shown in the other, and the last view parked wins. T3 replaces this with the master and follower views. The two tasks were built back to back for this reason, and nothing should be released between them.
- **Closing the last tab of a document with unsaved edits asks first, in a banner inside the pane, not a modal.** Save, Don't save and Cancel. Save that fails keeps the tab open and shows the reason. Closing a tab while another tab shows the same document asks nothing, because the edits stay visible there. Closing the app never asks (ISC-49, P2-T6): hot exit keeps the edits instead.
- **Ctrl+S is taken from the page whether or not it saves.** Save is disabled while the focused document is clean or read-only (the menu greys it), but the key handler still swallows the press, so the browser's own Save As never opens. A web test presses the key on a clean and on an edited document.
- **Saves run one at a time per document, and an edit made during a save stays unsaved.** The save sends a snapshot (text and endings at that moment). When it lands, only that snapshot is marked saved; the document is clean only if it still equals it. A test holds the host's write open and types in the meantime.
- **Dirty means "different from what is on disk", not "edited".** A document is compared (text and endings) with its last saved snapshot, so undoing back to the saved text clears the marker.
- **Opening works with no folder open.** The store has no notion of a root: `openPath` asks the host, and Rust decides by its path policy whether the file was chosen by the user. That is what ISC-98 rests on, with `access.rs` covering the Rust side (a granted loose file is readable, its neighbour is not). Opening a file that is already open, in any spelling of its path, focuses its tab, in the pane that has it.
- **Open dialog from the page: `pick_files` returns the chosen paths, then `open_file` for each.** The grant happens inside `pick_files`, in Rust, before the page learns the path. The page has no command that grants access, so a path it invents is refused. In the real app this was checked directly: with the DevTools port, `open_file` and `read_file` on a real file nobody chose both return `not-allowed`.
- **The mock host has in-memory files** (`createMockHost`, `src/platform/mockFiles.ts`), split into text and endings the way `eol.rs` does, with Windows-like case-insensitive paths, ids that stay the same for the same file, and a read-only file kind. `pnpm dev` ships five demo files (LF, CRLF and mixed) and Ctrl+O opens the next one in turn, since a browser tab has no dialog. Tests hand the app their own host with `setHost`.
- **The page half of the frame has a byte-for-byte pin shared with Rust.** `the_bytes_match_what_the_page_expects` (Rust) and `reads the bytes Rust writes for the same document` (web) build or read the same 59 bytes. If either side changes the layout, one of the two fails.
- **The line-ending field exists now, with its core job.** Save needs it, so `src/editor/lineEndings.ts` is real in T2: it follows each edit, shifts later breaks' indices, and gives a new break the ending of the line it was typed on. T4 still owns the two gaps from the spike (undo restoring a deleted break's old ending, and moved text keeping its endings) and the property tests.
- **A small fix found while checking the real window:** the `not-allowed` message carried Windows' verbatim prefix (`\\?\C:\...`), and the page shows that text. It now goes through `display_path`, and a test pins it.
- **No new crates and no new Tauri permissions in this task.**
- **Mutation proofs (the code broken on purpose, then restored):**
  - The frame ignoring its 4-byte padding: both frame tests fail.
  - The endings field not shifting later breaks after an edit: `keeps later line breaks with their own endings when lines are added or removed before them` fails.
  - Save sending no endings: that test and `keeps the line endings the file had` fail.
  - The restored code passes all 34 tests in `tests/platform` and `tests/documents`.
- **Checked in the browser (Claude in Chrome on `pnpm dev`):** the app starts with no tabs. Ctrl+O opens README.md and notes.md in tabs, with content and the path in the status bar. Typing shows the dirty dot, and Ctrl+S clears it and writes the file (the original text plus what was typed). A mixed-endings file (LF, CRLF and CR) saved with one character added at the start comes back as `>LF line`, a CRLF, `old Mac line`, a lone CR, `last line`, byte for byte. Closing an edited tab shows the banner, and Don't save closes it and leaves the file alone. No console errors.
- **Not checked in the real window: the native Open dialog, and a save through the real Rust path.** The desktop was locked for this whole session (`LogonUI.exe` running, and a screenshot showed the lock screen), so real OS input was not possible and I sent no more keys after one Ctrl+O that reached the lock screen. What was checked there: the app starts as the Tauri host, and the path policy refuses a file nobody chose. The dialog and a real save are covered by Rust tests and by the browser run, not by a human-style run in the window, and I will repeat them in the real window with P2-T6's checks.
- **How the real app was started this time.** The repo's Vite server was already listening on port 1420 (not started by me), so `pnpm tauri dev` would have collided with it. The app was run with `cargo run` from `src-tauri` against that server, with `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=9222`, and stopped afterwards. The Vite server was left running.
