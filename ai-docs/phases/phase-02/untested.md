# Phase 2: what was not tested, and how to test it later

Everything below was skipped on purpose or could not be done in the Phase 2 runs. Each entry says why, and how to check it when there is time. The decisions behind them are in [decisions.md](decisions.md).

| # | Gap | Why it was skipped | How to test it |
|---|---|---|---|
| 1 | The native Open dialog | No harness can drive a native dialog. Files were opened through the perf-only `perf_grant_file` command and the store. | By hand in `pnpm tauri dev`: press Ctrl+O, pick a file, a folder of files and a file that is already open. Check the tab opens, the same file opens once, and cancelling does nothing. |
| 2 | Windows logoff or shutdown closing the app | It would end the session running the work. The close handler is the same one the caption button and `CloseMainWindow` use, and both were checked. | In a throwaway Windows session: type in a file, log off at once, log back in, start the app. The typed text should be there. Windows may kill the process before the 3 s timer, so a miss here tells you the journal interval is the real limit. |
| 3 | The 3 s close timer in Rust | Only the page side of the close flow is tested. A page that never answers needs a stuck or crashed page. | In a debug build, temporarily make `closeRequested` in `src/documents/session.ts` hang (`await new Promise(() => undefined)` as its first line), close the window and time it: it should close after about 3 s. Revert the change. For an automated test, split `CloseHook` from the window handler in `src-tauri/src/lib.rs` so the timer can run against a fake window. |
| 4 | A crash or power cut during a session write | The rename is the one saves use, and it is tested stage by stage there. A real power cut cannot be scripted. | Use the `Stage` hooks in `src-tauri/src/fs/atomic.rs` from a session test that stops after the temp file is written and before the rename, then load: the old snapshot must come back and the temp file must be swept. A real cut: copy the data folder to a USB stick, pull the plug during typing, and check `session.json` still parses. |
| 5 | A second instance sharing the data folder | Nothing stops a second instance yet, so there is nothing defined to test. | Add a single-instance guard first (a window-management decision for a later phase), then start two copies and check the second one focuses the first. Until then, start two copies with the same `MDMATE_DATA_DIR` and confirm the last writer wins and nothing crashes. |
| 6 | Typing in a large file in the real window | The unit tests cover the mode and the saves. The typing cost at size is the P0 measurement, taken with its own scenario. | `pnpm perf typing-5mb` and `typing-10mb` measure the editor's work per key on plain source. By hand: open `tests/fixtures/generated/realistic-5mb.md`, type for a minute and watch for lag. |
| 7 | The journal's cost while typing | `journal-cost` measures a write on its own (frames late per write). No run had the journal live during `typing-1mb`, because that scenario builds its own editor state and bypasses the workbench. The "at most 1 frame in 60" figure is worked out from it. | Add a scenario that opens the file through the store, starts the journal with `startJournal`, and types with the same key timings as `typing-1mb`. Compare work per key with and without the journal. |
| 8 | An outside write while the window is minimized or on another desktop | Only checked with the window in front. | Open a file, minimize the app, change the file from a shell, restore the window: the tab should show the new text, or the conflict banner if it had edits. |
| 9 | The notice banner in a large-file tab while typing | Checked on open only. | Open a file above 3 MiB, type, switch tabs and back: the notice should stay on that tab and not appear on others. |
