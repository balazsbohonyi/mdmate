# Phase 6: what was not tested, and how to test it later

Everything below was skipped on purpose or could not be done in the Phase 6 runs. Each entry says why, and how to check it when there is time. The decisions behind them are in [decisions.md](decisions.md).

| # | Gap | Why it was skipped | How to test it |
|---|---|---|---|
| 1 | The native folder picker behind Open Folder (ISC-192) | The dialog opens from a real Ctrl+Shift+O, but I could not drive it safely: keystrokes from a script go to whichever window has focus, and twice they did not reach the dialog. Rust's grant and the page's handling of the answer are both tested; only the picker itself in the middle is by hand. | In the app press Ctrl+Shift+O, choose a folder, and see it appear in the sidebar; restart and see it come back. Also try Cancel (nothing changes) and a folder on a network drive (refused with a message). |
| 2 | Drop positions at 125% display scale on the tree (the T3 run at 1.25 landed correctly on a pane, a tab strip and editor text) | The real drops ran at 100% (`devicePixelRatio` 1). `toCssPosition` is unit-tested, but a wrong ratio would only show as a drop landing a row off on the tree. | On the laptop screen at 125%, drag a folder from Explorer onto the sidebar's empty area and onto a tree row, and see that the first becomes a root and the second does not. |
| 3 | Network and removable drives as roots | Only local temp folders were used. | Open a folder on a mapped network drive and on a USB stick; see the listing, then pull the stick out and see the tree report the folder instead of crashing. |
| 4 | A symlink or junction inside a root that points outside it | The tree counts a symlink to a folder as a folder and `Access` resolves it before checking, but no test builds one. | Make a junction in a root to a folder outside it, open the junction in the tree, and see that listing is refused with `not-allowed`. |
| 5 | Very deep trees and long names | The 10,000-entry case is one flat folder. | Open a folder with 15 levels and names near 255 characters; check that indentation and the truncated names stay readable. |
| 6 | The watcher after the folder itself is deleted or renamed while open | The folder's own row goes when its parent is listed again, but no real run deleted an open folder. | Open a folder in the tree, delete it in Explorer, and see its row go and nothing report an error. |
| 8 | Moves and copies on network or removable drives, and a move across volumes | Only local temp folders. A cross-volume move is refused by design (decisions.md); that refusal is tested through the error kind, not on a real second drive. | Move a file from a folder on C: to a root on a USB stick and see the message; copy a folder to a network share and see it arrive whole. |
| 9 | Recycle Bin on macOS and Linux, and a drive with no bin | The `trash` crate is called through `Platform`; only Windows ran. | Delete a file in the tree on macOS (it should land in the Trash) and on Linux; on a USB stick with no bin, see an error instead of a silent delete. |
| 10 | Dropping a folder that holds links | Rust tests skip and count links in a copy; a real Explorer drop of a tree with a junction inside was not tried. | Drop a project folder with a junction inside onto a tree folder and read the count of skipped links. |
| 7 | The macOS and Linux tree | CI compiles them; nothing ran. The path keyer assumes case-insensitive file systems everywhere except Linux. | Open a folder on macOS (case-insensitive by default) and on a case-sensitive volume, and open two folders that differ only in case. |
| 11 | Animated, very large (hundreds of MB) and broken image files | Only small generated PNGs and one 2400 x 1600 mock image were shown. | Open a 100 MB photo, an animated GIF and a PNG with a bad header; the first should fit and pan, the second play, the third show "This image could not be shown." |
| 12 | Dropping many files at once (dozens) | The real drops used two files. | Select 40 files in Explorer and drop them on a pane; check that all open as tabs, in order, with no stall. |
| 13 | A drop landing at 125% display scale on a pane, strip or text | The T3 real run was at scale 125% and the drops landed correctly, but only at one chosen spot each, and not on the tree rows. | Drop on the very edge of a pane, on the strip between two tabs, and on the border between two panes. |
| 14 | The scanner on a real workspace of thousands of files | Tests use small fixtures; no timing was taken (the typing gate belongs to P6-T6). | Point the walker at a large notes folder and a `node_modules`-sized tree, and check the count and the time. |
| 15 | A symbolic link (not a junction) and a network or removable root in the walker | The test makes a junction; a symbolic link needs a privilege, and no network share was used. | Run the walker over a root that holds a symbolic link to a folder and over a mapped network drive. |
| 16 | Latin-1 and UTF-16-without-mark files holding links | They are reported and not rewritten (decisions.md); nothing in the app shows the list yet. | Rename a file linked from a Latin-1 note after P6-T6 and see the note listed as skipped. |
| 17 | Unusual Markdown: links in indented code, definitions split over two lines, setext or table cells, and unquoted HTML attributes that end in a slash | The scanner leaves or reads them by the rules in decisions.md; no real document set was checked. | Run the scanner over a few real READMEs and compare its link list with a Markdown renderer's. |
| 18 | A rewrite on a network drive, on a file locked by another program, and on a file with the Archive or System attribute | The tests lock a file with the read-only attribute only. | Rename a file linked from a note that another program holds open (an editor with a share lock) and see the note listed as failed while the others are written. |
| 19 | A very large workspace for the plan, cold | `typing-during-scan` plans over 8,015 files (9.6 MB) at about 0.93 s a scan, but only after two warm-up launches had read them. In the first batch the run right after the warm-ups finished no scan in the whole typing window, and I do not know why. | Reboot, open a workspace of a few thousand notes on a spinning or slow disk, rename a file linked from many places and time the first prompt. |
| 20 | Links in Markdown the scanner does not model (setext headings, tables, footnotes, wikilinks) after a rename | Not in the plan; see row 17. | Rename a file linked from a table cell and from a wikilink; the table cell link should follow, the wikilink stays. |
| 21 | `links.confirmRewrite: false` set by the user | The setting exists only in memory (`src/lib/settings.ts`); `settings.json` arrives with P8-T1, so tests set the value and no run reads it from a file. | After P8-T1, set it to false in `settings.json`, restart, rename a linked file and see no prompt. |
| 22 | The prompt in the real window with Don't update and Cancel | Real-window runs answered Update links; Don't update and Cancel are proven by page tests and the mock page only. | Rename a linked file in the real app and answer each; with Cancel nothing moves, with Don't update the file moves and the links keep the old text. |
| 23 | A scan that is Stopped in the real window, and a dirty document in an encoding mdmate does not write | Stop is proven by Rust and page tests (the progress closure sees the flag); no real run clicked it, and no real run opened a Latin-1 file. | Plan a rename over a large workspace and click Stop; open a Latin-1 note that links to the file and read the notice. |
| 24 | Two web tests that failed once each in full runs | `checkbox` and `blockquotes` editor tests failed in two of three full runs of `pnpm test:web` and pass alone; I did not capture the messages. | Run `pnpm test:web` several times keeping the output, and read the message the next time one fails. |
| 25 | The first Ctrl+P in a very large workspace (the 250,000-file cap and the cost of the first build) | The cap is proven with a small cap in a test, and the picker was run on a workspace of a few files; no run timed a build over tens of thousands of files or reached the cap for real. | Open a folder with 100,000 or more files (a `node_modules` tree), press Ctrl+P and time the first list; open it again right after and see the list stay put while it is read again. |
| 26 | Ctrl+P and Ctrl+Shift+P on a keyboard layout other than the one on this machine, and in an input method editor | The real OS keys were sent as virtual-key codes on this machine. The picker ignores keys during composition (`isComposing`), but no real IME was used. | Switch to a layout where P is not on the same key, and type Hungarian or Japanese into the picker box; the shortcuts should still open it and the composition should not choose a row. |
| 27 | A symlink, junction or very deep folder inside a workspace | The index uses the walk of the link scan, which does not follow links; the tests have no symlink or junction, and Windows needs a privilege to make a symlink. | Make a junction inside a workspace that points back to its parent and press Ctrl+P: it should list the files once and not loop. |
| 28 | Ctrl+P with two folders open, in the real window | The two-root prefix is proven by a Rust test and the mock host; the real run used one folder. | Open two folders, press Ctrl+P and see each path start with its folder name. |
