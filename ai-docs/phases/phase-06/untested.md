# Phase 6: what was not tested, and how to test it later

Everything below was skipped on purpose or could not be done in the Phase 6 runs. Each entry says why, and how to check it when there is time. The decisions behind them are in [decisions.md](decisions.md).

| # | Gap | Why it was skipped | How to test it |
|---|---|---|---|
| 1 | The native folder picker behind Open Folder (ISC-192) | The dialog opens from a real Ctrl+Shift+O, but I could not drive it safely: keystrokes from a script go to whichever window has focus, and twice they did not reach the dialog. Rust's grant and the page's handling of the answer are both tested; only the picker itself in the middle is by hand. | In the app press Ctrl+Shift+O, choose a folder, and see it appear in the sidebar; restart and see it come back. Also try Cancel (nothing changes) and a folder on a network drive (refused with a message). |
| 2 | Drop positions at 125% display scale on the tree (the T3 run at 1.25 landed correctly on a pane, a tab strip and editor text) | The real drops ran at 100% (`devicePixelRatio` 1). `toCssPosition` is unit-tested, but a wrong ratio would only show as a drop landing a row off on the tree. | On the laptop screen at 125%, drag a folder from Explorer onto the sidebar's empty area and onto a tree row, and see that the first becomes a root and the second does not. |
| 3 | Network and removable drives as roots | Only local temp folders were used. | Open a folder on a mapped network drive and on a USB stick; see the listing, then pull the stick out and see the tree report the folder instead of crashing. |
| 4 | A symlink or junction inside a root that points outside it | The tree counts a symlink to a folder as a folder and `Access` resolves it before checking, but no test builds one. | Make a junction in a root to a folder outside it, open the junction in the tree, and see that listing is refused with `not-allowed`. |
| 5 | Very deep trees and long names | The 10,000-entry case is one flat folder. | Open a folder with 15 levels and names near 255 characters; check that indentation and the truncated names stay readable. |
| 6 | The watcher after the folder itself is deleted or renamed while open | The folder's own row goes when its parent is listed again, but no real run deleted an open folder. | Open a folder in the tree, delete it in Explorer, and see its row go and nothing report an error. |
| 8 | Moves and copies on network or removable drives, and a move across volumes | Only local temp folders. A cross-volume move is refused by design (decisions.md); that refusal is tested through the error kind, not on a real second drive. | Move a file from a folder on C: to a root on a USB stick and see the message; copy a folder to a network share and see it arrive whole. |
| 9 | Recycle Bin on macOS and Linux, and a drive with no bin | The `trash` crate is called through `Platform`; only Windows ran. | Delete a file in the tree on macOS (it should land in the Trash) and on Linux; on a USB stick with no bin, see an error instead of a silent delete. |
| 10 | Dropping a folder that holds links | Rust tests skip and count links in a copy; a real Explorer drop of a tree with a junction inside was not tried. | Drop a project folder with a junction inside onto a tree folder and read the count of skipped links. |
| 7 | The macOS and Linux tree | CI compiles them; nothing ran. The path keyer assumes case-insensitive file systems everywhere except Linux. | Open a folder on macOS (case-insensitive by default) and on a case-sensitive volume, and open two folders that differ only in case. |
| 11 | Animated, very large (hundreds of MB) and broken image files | Only small generated PNGs and one 2400 x 1600 mock image were shown. | Open a 100 MB photo, an animated GIF and a PNG with a bad header; the first should fit and pan, the second play, the third show "This image could not be shown." |
| 12 | Dropping many files at once (dozens) | The real drops used two files. | Select 40 files in Explorer and drop them on a pane; check that all open as tabs, in order, with no stall. |
| 13 | A drop landing at 125% display scale on a pane, strip or text | The T3 real run was at scale 125% and the drops landed correctly, but only at one chosen spot each, and not on the tree rows. | Drop on the very edge of a pane, on the strip between two tabs, and on the border between two panes. |
| 14 | The scanner on a real workspace of thousands of files | Tests use small fixtures; no timing was taken (the typing gate belongs to P6-T6). | Point the walker at a large notes folder and a `node_modules`-sized tree, and check the count and the time. |
| 15 | A symbolic link (not a junction) and a network or removable root in the walker | The test makes a junction; a symbolic link needs a privilege, and no network share was used. | Run the walker over a root that holds a symbolic link to a folder and over a mapped network drive. |
| 16 | Latin-1 and UTF-16-without-mark files holding links | They are reported and not rewritten (decisions.md); nothing in the app shows the list yet. | Rename a file linked from a Latin-1 note after P6-T6 and see the note listed as skipped. |
| 17 | Unusual Markdown: links in indented code, definitions split over two lines, setext or table cells, and unquoted HTML attributes that end in a slash | The scanner leaves or reads them by the rules in decisions.md; no real document set was checked. | Run the scanner over a few real READMEs and compare its link list with a Markdown renderer's. |
| 18 | A rewrite on a network drive, on a file locked by another program, and on a file with the Archive or System attribute | The tests lock a file with the read-only attribute only. | Rename a file linked from a note that another program holds open (an editor with a share lock) and see the note listed as failed while the others are written. |
| 19 | A very large workspace for the plan, cold | `typing-during-scan` plans over 8,015 files (9.6 MB) at about 0.93 s a scan, but only after two warm-up launches had read them. In the first batch the run right after the warm-ups finished no scan in the whole typing window, and I do not know why. | Reboot, open a workspace of a few thousand notes on a spinning or slow disk, rename a file linked from many places and time the first prompt. |
| 20 | Links in Markdown the scanner does not model (setext headings, tables, footnotes, wikilinks) after a rename | Not in the plan; see row 17. | Rename a file linked from a table cell and from a wikilink; the table cell link should follow, the wikilink stays. |
| 21 | `links.confirmRewrite: false` set by the user | The setting exists only in memory (`src/lib/settings.ts`); `settings.json` arrives with P8-T1, so tests set the value and no run reads it from a file. | After P8-T1, set it to false in `settings.json`, restart, rename a linked file and see no prompt. |
| 22 | The prompt in the real window with Don't update and Cancel | Real-window runs answered Update links; Don't update and Cancel are proven by page tests and the mock page only. | Rename a linked file in the real app and answer each; with Cancel nothing moves, with Don't update the file moves and the links keep the old text. |
| 23 | A scan that is Stopped in the real window, and a dirty document in an encoding mdmate does not write | Stop is proven by Rust and page tests (the progress closure sees the flag); no real run clicked it, and no real run opened a Latin-1 file. | Plan a rename over a large workspace and click Stop; open a Latin-1 note that links to the file and read the notice. |
| 24 | Two web tests that failed once each in full runs | `checkbox` and `blockquotes` editor tests failed in two of three full runs of `pnpm test:web` and pass alone; I did not capture the messages. | Run `pnpm test:web` several times keeping the output, and read the message the next time one fails. |
| 25 | The first Ctrl+P in a very large workspace (the 250,000-file cap and the cost of the first build) | The cap is proven with a small cap in a test, and the picker was run on a workspace of a few files; no run timed a build over tens of thousands of files or reached the cap for real. | Open a folder with 100,000 or more files (a `node_modules` tree), press Ctrl+P and time the first list; open it again right after and see the list stay put while it is read again. |
| 26 | Ctrl+P and Ctrl+Shift+P on a keyboard layout other than the one on this machine, and in an input method editor | The real OS keys were sent as virtual-key codes on this machine. The picker ignores keys during composition (`isComposing`), but no real IME was used. | Switch to a layout where P is not on the same key, and type Hungarian or Japanese into the picker box; the shortcuts should still open it and the composition should not choose a row. |
| 27 | A symlink, junction or very deep folder inside a workspace | The index uses the walk of the link scan, which does not follow links; the tests have no symlink or junction, and Windows needs a privilege to make a symlink. | Make a junction inside a workspace that points back to its parent and press Ctrl+P: it should list the files once and not loop. |
| 28 | Ctrl+P with two folders open, in the real window | The two-root prefix is proven by a Rust test and the mock host; the real run used one folder. | Open two folders, press Ctrl+P and see each path start with its folder name. |
| 29 | The native Save As dialog on a machine with other settings (Explorer showing extensions, a network folder, a read-only folder, a very long path) | It was driven through UI Automation on this machine only: the File name box showed the name without its extension, which is this machine's Explorer setting. The overwrite question was the Windows "Confirm Save As" and was answered Yes. | Save As into a read-only folder and into a folder with a 250-character path; turn on "File name extensions" in Explorer and check the name box shows `meeting-notes.md`. |
| 30 | Save As of a file in an encoding mdmate cannot read, other than Latin-1 | The Latin-1 fixture came out as UTF-8 with the accented letters kept. A UTF-16 file with no BOM would be shown through the same fallback, so the copy would hold what is shown, not the original characters. No such file was tried. | Open a UTF-16 (no BOM) file, Save As, open the copy and compare the text with the original. |
| 31 | A typing run with an input method editor in an untitled tab, and the name box of the dialog in another language | Only plain text typing through CDP and real OS key chords were used. | Type Japanese or Hungarian into an untitled tab, kill the app, restart, and compare the text; use the dialog on a system set to another display language. |
| 32 | Revert File right after a file is deleted while the window has focus | The menu state is refreshed on tab change, focus and menu open, and again at the request, so the menu can show Revert as available for a moment after a delete; the request itself looks again and says the file is gone. The case was tested with the mock host and the real check deleted the file and then opened the menu. | Delete the open file in Explorer, click back into the window and open the menu at once: Revert File should be off. |
| 33 | Open Recent with a file on a drive that is not there (a USB stick taken out, a network share offline) | Missing files are dropped when the list is read; a path on an offline share may take a long time to answer on Windows, and nothing here measured that. | Add a file from a network share, disconnect, open the File menu and time the Open Recent submenu. |
| 34 | Rename from the tab menu or F2 for a file in the second of two open folders, and Reveal in Sidebar for a file under a folder with thousands of entries | Only one open folder was used in the real run, and the folder was one level deep. Nested and two-folder choices are proven by page tests. | Open two folders, right-click a tab of a file in the second, choose Rename and Reveal in Sidebar; do the same in a folder with a long listing. |
| 35 | Find File References on a very large workspace (thousands of Markdown files, the 2000-link cut) in the real window | The cut is proven with a small limit in a Rust test; the real run had four files. | Make a folder with 3000 files that link to one file and run the command; see the cut notice and the time. |
| 36 | The References panel after a rename or an edit | The list is a snapshot; no test or run changes a file after a search to see the panel. It is meant to stay as it was, but that was not checked in the real window. | Run Find File References, rename a listed file, and look at the panel. |
| 37 | Find File References on a file with a reference-style link or an HTML link, in the real window | The real fixture used inline links; reference definitions, HTML and angle brackets are proven by the Rust fixture test only (the mock host reads inline links only). | Link to a file with each form in a real folder and run the command. |
| 38 | Right-click on a tab with a touch screen or a pen, and the menu on a tab that is partly scrolled out of the strip | Real runs used a mouse and tabs that all fit. | Open many tabs so the strip scrolls, right-click one at the edge, and use a pen. |
| 39 | The reason for a disabled Rename for keyboard, touch and screen reader users | The reason is a shadcn tooltip shown on mouse hover (looked at in the real window, in both themes). A disabled item cannot take keyboard focus, so Rename or F2 on such a file is silent, and no run used a screen reader or touch. | Open a file outside every folder, press F2, and try the menu with the keyboard and a screen reader; decide whether the status bar should say it. |
| 40 | Open Folder on macOS and Linux, and Open Containing Folder selecting the file in Explorer | The Rust command and the page are tested with a fake OS, and a real Windows run saw Explorer open the folder (read from the shell's window list). The macOS `open` and Linux `xdg-open` branches were never run, and no run checked that Explorer selected the file for Open Containing Folder (that code is unchanged from the old Reveal). | On each OS, right-click a folder and choose Open Folder; right-click a file and choose Open Containing Folder and see the file selected. |
| 41 | The sidebar edge with a touch screen or a pen, on a high-DPI display at a root font size other than 16 px, and while a dialog or menu is open | Real runs used a mouse (CDP mouse events) at 100% scale. The 12rem limit is stored as 192 px, so a different root font size would make it 12 rem only at the default size. | Drag the edge with a finger on a touch screen, on a 150% display, and with the root font size changed in the WebView. |
| 42 | A workspace folder added while a document with a `../` image is already open | The boundary is read at scan time and adding a folder does not trigger a scan, so the placeholder should stay until the next edit or reopen. Unit tests cover the boundary read; no run added a folder to a running window. | Open a loose document with a `../img/p.png` image, add its parent as a workspace folder, and see whether the image appears without an edit. |
| 43 | An image tab remembered while its pane is split, resized or the picture file is replaced by a different size | Unit tests recall the same spot in a differently sized pane, and a real run switched tabs in one pane. No run split the pane or replaced the file while the tab was in the background. | Zoom an image, split the pane or resize the window, switch away and back; then overwrite the image on disk with a larger one and switch back. |
| 44 | A menu key hint on a tab or tree row that is not the active tab | Ctrl+W, F2 and Shift+F12 act on the active tab, so right-clicking a background tab, or a tree row other than the active tab's file, still shows the key that works on the active tab. Accepted by the owner (option A); not tested because the hint is the same text for every row. | Show the keys only for the active tab, or give the tree its own commands that act on the right-clicked row. |
| 45 | Line breaks inside a long path in a hint | A path with no spaces is cut at the edge of the hint (e.g. "wit" / "h/no"), because the browser gives no break point after a slash. A real run measured it; no change was made, since a cut is unavoidable for a word longer than the line. | Insert a break point after each slash and backslash when drawing a path hint, and check that copying the text is not affected. |
| 46 | The shape of the pointer cursor over a followed link | A real Ctrl-held mouse move was sent over the DevTools port and the computed cursor was `pointer`; the cursor the OS draws could not be seen by a script. | In the app hold Ctrl over a link: the arrow turns into a hand. Let go: it turns back into the text beam. Try a missing link and a link inside a table: no hand. |
| 47 | Right-click Cut, Copy and Paste on editor text still shows the browser menu | Chosen on purpose (owner: block except text), so Inspect is reachable from editor text. Only the cancelling was run in the real window, not the menu items themselves. | Right-click selected editor text and check that Cut, Copy and Paste work. If the whole menu should go, build an in-app editor menu first. |
| 48 | A read-only file opens editable and fails only when saved | The owner asked for a clear message at save time, which is done. Opening such a file as read-only (no typing, a notice at the top) would be a further change; today the attribute is read only when the save is refused. | Open a file with the read-only attribute, type, press Ctrl+S: the notice names the cause. Decide whether it should open read-only instead. |
| 49 | Error wording for rename, delete, copy and open failures | They all go through the same mapper and the cases are unit-tested, but the real window ran only the read-only save. | Try renaming a file that another program has open, deleting one on a drive with no Recycle Bin, and copying onto a full disk; each should show one plain sentence and no code. |
| 50 | A tab's scroll place is not kept across a restart | It lives in memory with the tab; the session file stores tabs and carets only. A restored tab starts at its caret. | Scroll a file, quit, reopen: the file opens at its caret, not at the old scroll place. Decide whether the session should store it. |
| 51 | The tab strip's hover tooltips | The "New File" and "Open Tabs" hints are tested for being tooltips and not native titles, but the hover itself was not driven in the real window (pointer hover delay). | Hover + and the chevron: a themed tooltip appears below each. Open the chevron menu with the keyboard (Enter on it) and pick a tab with the arrow keys. |
| 52 | The tab list with hundreds of tabs | The list is one menu item per tab with no virtual list; 24 and 40 tabs were checked. | Open 200 files, open the chevron: it scrolls and stays responsive. |
| 53 | Scrollbar look on a high-contrast or forced-colors Windows theme | Forced colors replace custom scrollbar colors with system ones; not looked at. | Turn on a Windows high-contrast theme: the bars should stay visible. |
